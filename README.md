# Sleep Stage Classification from EEG

Automated sleep staging from 13 EEG features, with an honest evaluation and an interactive Streamlit dashboard.

## Why this matters

Sleep disorders such as insomnia and sleep apnea are diagnosed from overnight recordings. A trained
technician scores those recordings **by hand**, one 30-second epoch at a time, which takes hours per
patient. Automatic staging can do a first pass in seconds and leave the expert to review.

This project classifies 30-second epochs into sleep stages and, just as importantly, measures how well
that really works.

## What it does

- Classifies epochs into **5 AASM stages** (W, N1, N2, N3, REM), or the **6 original R&K stages**
  (stage 3 and stage 4 kept separate).
- Compares **4 models** (Random Forest, Random Forest + PCA, Hist Gradient Boosting, Logistic Regression)
  against **2 baselines** (always the most frequent stage, and random guessing by class frequency).
- Compares **5 ways of handling class imbalance**: none (class weights), SMOTE, Borderline-SMOTE, ADASYN
  and selective SMOTE.
- Evaluates every model under **two split schemes**, a random epoch split and a blocked time split, to
  expose data leakage between neighbouring epochs.
- Reports accuracy, macro F1, balanced accuracy, **Cohen's kappa**, per-class scores and confusion matrices.
- Serves everything in an **11-page Streamlit dashboard**, including a predict page for new CSV files.

## Setup

Python 3.11+ (developed on 3.13).

```bash
python -m venv .venv
```

Activate it (`.venv\Scripts\activate` on Windows, `source .venv/bin/activate` on macOS/Linux), then:

```bash
pip install -r requirements.txt
```

## Train

Run from the project root:

```bash
python scripts/train.py
```

The full run (80 experiments with hyperparameter search) takes about 15–20 minutes on a 16-core machine.
Useful options:

| Option | Effect |
| --- | --- |
| `--quick` | Baselines + Random Forest only, no tuning (about 2 minutes) |
| `--no-tune` | Skip the hyperparameter search |
| `--data PATH` | Use a different feature CSV |
| `--output DIR` | Write artifacts somewhere else |
| `--save-all-models` | Also save models for non-default resampling runs |

It writes to `artifacts/`:

- `metrics.json`: every experiment's CV and test metrics, the PCA decision and resampling counts
- `predictions.csv`: test-set predictions and class probabilities for every experiment
- `cv_folds.csv`: per-fold cross-validation scores
- `feature_importance.json`: impurity and permutation importance
- `models/*.joblib`: fitted pipelines

## Dashboard

```bash
streamlit run app/streamlit_app.py
```

The sidebar picks the split type, wake trimming, class setup, model and resampling strategy. Pages:

1. **Overview**: problem, dataset summary, headline metrics against the baseline
2. **Data explorer**: class distribution, features by stage, correlations, PCA scatter, hypnogram
3. **Class imbalance & resampling**: class counts after each strategy and their scores
4. **Model performance**: confusion matrices, per-class scores, CV folds, CV vs test, ROC and PR curves
5. **Leakage check**: the same model under the random and blocked splits
6. **Model comparison**: every model against the baselines, plus the PCA decision
7. **Feature importance**: impurity and permutation importance
8. **Hypnogram**: true vs predicted stages over time, with mistakes highlighted
9. **Predict**: upload a feature CSV and get stages, probabilities and a hypnogram
10. **Sleep insights (demo)**: rule-based night summary, clearly marked as not validated
11. **Limitations**

If `artifacts/` is missing, the dashboard says so and offers a quick retrain from the sidebar.

## Tests

```bash
python -m pytest
```

The suite checks that the label map covers every label in the CSV, that N3 merging gives exactly 5 classes,
that blocked splits never share a block between train and test (or between CV folds), that resampling only
touches training data, that every model pipeline fits and predicts, and that the insights demo handles
every stage label.

## How the evaluation works

**Labels.** The CSV uses Rechtschaffen & Kales stages. The 5-class setup merges stages 3 and 4 into N3,
as the AASM standard has since 2007. 6-class models are also scored after the same merge, so both setups
compare on equal terms.

**Random split.** Stratified 80/20 split of individual epochs, with stratified 5-fold CV on the training
part. This is what the original scripts did, and it leaks: neighbouring 30-second epochs are near-identical,
so most test epochs have a near-copy in training.

**Blocked split.** The time-ordered recording is cut into 10 contiguous blocks. Two whole blocks are held
out as the test set, chosen so each stage's share of test epochs is as close as possible to 20%. Training
epochs within 5 epochs of a test block are dropped, and CV uses `StratifiedGroupKFold` over blocks. The
dataset has no subject id, so this is the most honest split available.

**Wake trimming.** The recording has about 6 hours of wake before sleep and 9 hours after. The trimmed
variant keeps 30 minutes of wake on each side of the sleep period.

**Resampling** runs inside the model pipeline, so it only ever sees training folds. `k_neighbors` shrinks
automatically for tiny classes, and a class with one training epoch is left alone.

**Tuning.** A small grid search runs inside cross-validation on the training rows. Other resampling
strategies reuse the parameters tuned with SMOTE. The test set is never used to choose anything.

**Macro F1** is averaged over the classes present in the evaluated set, because blocked folds don't always
contain every stage.

## What changed from the original scripts

The original `sleep_stage_classifier.py`, `chart_1.py` and `demo.py` are kept unchanged in `legacy/`.

| Problem in the original | Fix |
| --- | --- |
| `chart_1.py` defined the classifier class twice; an empty placeholder overrode the real one | One implementation in `src/sleepstage/` |
| Three ~95% duplicated scripts | Merged into one package |
| Day-quality code used `'Wake'` / `'Sleep stage REM'`, but the data says `'Sleep stage W'` / `'Sleep stage R'`, so those stages silently scored 0 | One label map in `config.py`, validated on load |
| Emoji in `print()` crashed on Windows consoles | `logging` with plain text |
| Hard-coded path to a Downloads folder | `data/` folder, `--data` option or `SLEEPSTAGE_DATA` |
| Selective SMOTE got a placeholder CV score of 0 and a gap of 0, which won the comparison unfairly | Every strategy gets real cross-validation |
| 5-class and 6-class F1 compared directly | 6-class results are also scored after merging into N3 |
| Selective SMOTE threshold said 20 in the comment and 15 in the code | One named constant |
| Day-quality demo sampled rows that could be training data, unseeded | Replaced by a sequence-based demo on test predictions or true labels |
| Day-quality compared a row's features with percentiles of unrelated features | Removed |
| `warnings.filterwarnings('ignore')` and broad `except Exception` hid errors | Removed; only specific, expected cases are handled |
| Unused imports | Removed |
| Confusion matrix plot retrained the model | Dashboard reads saved predictions |
| Random epoch split only (leaky), no baselines, no kappa | Blocked split, baselines, kappa, balanced accuracy, per-class scores |
| PCA(6) used without justification | Compared with no PCA on blocked-split CV |

## Results

All numbers come from `artifacts/metrics.json` (full run with tuning, seed 42), scored on held-out test
epochs. κ is Cohen's kappa. The default resampling is SMOTE; baselines use none.

| Model | Random: Acc | Random: Macro F1 | Random: κ | Blocked: Acc | Blocked: Macro F1 | Blocked: κ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Baseline: always most frequent | 0.663 | 0.159 | 0.000 | 0.506 | 0.134 | 0.000 |
| Baseline: random by class frequency | 0.480 | 0.210 | 0.020 | 0.389 | 0.159 | -0.048 |
| Random Forest | 0.934 | 0.825 | 0.874 | 0.772 | 0.580 | 0.651 |
| Random Forest + PCA(6) | 0.902 | 0.745 | 0.814 | 0.763 | 0.526 | 0.632 |
| Hist Gradient Boosting | 0.943 | 0.839 | 0.890 | 0.868 | 0.699 | 0.788 |
| Logistic Regression | 0.911 | 0.765 | 0.831 | 0.848 | 0.615 | 0.763 |

Test sets: 561 epochs each. The blocked test set is blocks 0 and 5 of 10.

### Key findings

1. **The original evaluation was inflated by leakage.** The same tuned Random Forest scores κ 0.874 with a
   random epoch split but 0.651 when whole blocks of time are held out (full recording), and 0.747 vs 0.288
   on the trimmed recording. Under the random split, CV and test agree within 0.02; under the blocked split
   the gap grows to 0.14–0.19.
2. **Every model beats both baselines by a wide margin**, on every split. Always predicting the most
   frequent stage gets 51–66% accuracy but κ 0 and macro F1 ≈ 0.15.
3. **Under the honest split, the simpler and smoother models generalise better than Random Forest.**
   Hist Gradient Boosting reaches κ 0.788 / macro F1 0.699 (full recording) and κ 0.598 (trimmed);
   Logistic Regression reaches κ 0.763 and 0.569. The Random Forest falls to κ 0.288 on the trimmed
   recording, where it misses every deep-sleep test epoch. Choosing a model by blocked-split CV alone
   would pick Logistic Regression (CV Macro F1 0.784, test κ 0.763), which is the fair headline number.
4. **Trimming wake makes the task harder, not easier.** Most of the full recording's wake is easy to
   recognise; without it, the model has to separate N1, N2, N3 and REM, which is the clinically hard part.
5. **Resampling helps rare stages a little, and the differences are within noise.** SMOTE lifts the Random
   Forest's test macro F1 from 0.465 to 0.580 on the full recording, and Borderline-SMOTE/ADASYN lift it
   from 0.357 to about 0.48 on the trimmed recording. But blocked CV scores vary by ±0.15–0.25 between
   folds. Selective SMOTE equals SMOTE here, because no stage has between 2 and 15 training epochs.
6. **PCA(6) hurts** in all four blocked-CV comparisons, so the final models use all 13 features.
7. **Keeping stages 3 and 4 separate costs little.** The 6-class Random Forest, scored after merging into
   N3, performs like the 5-class model (κ 0.633 vs 0.651 full recording; 0.301 vs 0.288 trimmed).

## Limitations

- **One recording, no subject id.** All epochs come from a single night, so these results say nothing
  about a new person. The blocked split tests on unseen *time*, not unseen *people*. Real subject-wise
  evaluation needs features re-extracted from raw Sleep-EDF with a subject id; the plan is in
  `src/sleepstage/extract_features.py`.
- **Pre-scaled features.** The CSV was standardised over the whole file before any split, which leaks a
  little test information into training. It can't be undone without the raw signals.
- **Tiny classes, small test sets.** Stage 4 has 9 epochs in total. The full-recording blocked test set has
  only 3 deep-sleep epochs, so its N3 score is not meaningful; the trimmed blocked test set has 21.
- **Uneven blocked CV folds.** Several blocks are almost pure wake, so per-fold scores vary widely, and
  tuned CV scores are slightly optimistic (they come from the winning grid point).
- **Single public dataset** (Sleep-EDF format): one EEG montage, one scorer.
- **The sleep-insights page is a rule-based illustration.** It is not trained, not validated against any
  outcome, and not medical advice.
- **Comparison with published work.** Deep models trained on raw EEG from many subjects, such as
  DeepSleepNet (Supratak et al., 2017) and U-Time (Perslev et al., 2019), report roughly 80–85% accuracy
  and macro F1 around 0.75–0.80 on Sleep-EDF with subject-wise evaluation. Those results are not directly
  comparable with this project, which tests on unseen parts of one night.
